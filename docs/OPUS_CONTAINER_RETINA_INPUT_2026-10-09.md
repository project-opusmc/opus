# Vanilla server-selector click coordinates — October 9, 2026

## Observed failure and cause

The user could hover the Ranked Bedwars icon in a vanilla chest selector but
could not activate it. Investigation used launcher session
`1791520197443-91074`; its JVM PID 91169 exited during inspection, so no input
or further operation was sent to that process.

The session's stdout shows two Retina normalization hooks on `bfk`
(`EntityRenderer`, which produces hover coordinates), but none on raw vanilla
GUI classes. Standalone LaunchWrapper supplies raw names for both transform
arguments. `OpusStandaloneClassTransformer` recognized the Forge mapped GUI
prefix, so it skipped `axu` (`GuiScreen`) and `awi` (`GuiSlot`). The actual
vanilla `axu.k()` mouse handler then divided unscaled AppKit mouse points by
Minecraft's Retina backing framebuffer dimensions.

The real vanilla mouse-coordinate prelude reproduced the failure before any
production repair: for a 740×446 window at Retina 2× and Auto GUI scale, the
pointer inside the Bedwars slot region at `(257,101)` produced click
coordinates `(132,204)`. This is a client coordinate mismatch; no server
command or live server click was needed to reproduce it.

## Repair

The standalone dispatcher now resolves raw vanilla GUI names through the
existing pinned `notch-srg.srg` table and routes them to the existing absolute
mouse-coordinate transformer. The original bytecode class identity is
retained. Existing raw base targets, including `avo`, keep priority, so their
overlay/event/telemetry hooks remain intact. CEF input, non-GUI classes,
relative camera motion and wheel input keep their existing owners/contracts.
Artifact verification also requires the mapping resource used at class init.

The previously installed HUD client and CEF helper are unchanged. Their exact
verified bytes are reused as packaging inputs rather than rebuilding those
components for a standalone loader-only repair. No settings are reset.
